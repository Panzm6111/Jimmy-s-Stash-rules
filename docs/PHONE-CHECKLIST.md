# iPhone 验收清单与反馈

本地下载包不依赖公共文件发布；原远程分层方案需先发布main。官方文档阻塞与原生能力复核仍需处理。没有你的手机与账号，维护者不能代勾这些项目。

- [ ] 本地包模式：主配置没有rule-providers，分流规则已展开；广告增强含11份content内嵌JS、12条响应handler、32条拒绝重写、41个精确MITM主机。未配置任何未发布的公共资源下载URL。选择整合增强或单App覆写，不重复启用同款。
- [ ] 一体化订阅模式：从config/stash.yaml下载的配置已同时包含上述公共分流与专项。本机私人覆写关联正确、URL是本机值；刷新同一公共URL后再核对。不要重复添加core或广告增强。

- [ ] 记录 iOS/Stash 版本；Stash 真正接受该配置，合并预览含 16 个项目组且无重复/循环。
- [ ] 机场只在本机填写，刷新成功；总数及 SS/VLESS 数与机场后台一致，至少各测一种实际存在的协议。别把本仓库两个假节点当真实节点。
- [ ] 总代理从 REJECT 改为你自己选择的地区，普通海外 HTTPS 连通；延迟正常之后另测所需业务。
- [ ] OpenAI 与 Netflix 各选不同地区，调整其中一个不会改变另一个；改总代理只影响选“总代理”的软件。
- [ ] 在机场确实没有某地区节点时选择该池，确认访问被拒绝，**没有直连或其他地区出口**。若各池都有节点，可在本机临时副本中用不可能匹配的地区 filter 测试，保留 `^REJECT$`，测完删副本，不改仓库主文件。
- [ ] 在本机临时副本把“机场”替换为只含测试地址 `192.0.2.1` 的模拟节点（仅测试组使用），确认全失效也拒绝。不使用任何真人凭据、不改生产订阅、不为测试关闭证书验证。不会做这项可报告“未测”，不能凭离线工具代勾。
- [ ] 检查国内站、局域网设备、Apple通知/iCloud、Microsoft登录/常用服务的预期路径；规则显示的是域名匹配，不代表识别完整 App。
- [ ] 基础广告后测试本人常用 App 的登录、手动支付页面、消息、正常播放、领券。可选扩展广告单独加，再重复必要检查。
- [ ] 要用HTTP重写/响应广告模块时才生成并信任本机 CA；核对[模块目录](AD-MODULES.md)中的精确域名、handler与rewrite。按需逐个启用，不能只剩最后一个模块。分别测试广告效果和正常功能；无效就关闭，不能标“已去除”。
- [ ] 逐款测试冷启动/热启动；广告是否消失、是否出现空白等待；再测正常登录、支付、消息、播放、查物流/定位、本人普通领券。不用为了测试实际下单或消费。
- [ ] 云闪付/京东金融/铁路12306/携程等域名专项不需MITM；确认没有解密支付或银行主域。微信专项仅命中文章广告，不据此勾选朋友圈/视频号去广告成功。
- [ ] 更新前在本机记录“软件→地区”组名；刷新公共覆写/规则/JS后，私人 URL 和选择仍在。若选择丢失，记下触发步骤并重选，不发私人预览。
- [ ] 可在设备临时副本中给订阅 URL 填一个 `.invalid` 测试值，观察更新失败是否保留旧缓存；不要在主私人覆写中覆盖真实 URL。首次失败与曾成功后的缓存不是同一情况。
- [ ] “广告拦截→DIRECT”、逐个停用响应覆写、关闭MITM以及停用Stash，都能按教程恢复。
