# 旧离线包兼容说明

**当前日常方式已统一为原`config/stash.yaml`整合订阅，逐App开关不再属于需求。** 安装和更新请看[订阅教程](SUBSCRIBE.md)。已经接入成功的用户保留私人订阅覆写和已信任证书，刷新原链接即可，无需下载ZIP或再添加广告模块。

本页仅解释此前生成的`Jimmy-Stash.zip`，方便已使用旧离线包的人维护或迁移。文件名和目录名为兼容保留，不代表当前推荐流程。包内资源来自同一套维护源，广告逻辑与公开源一致，安装组合与更新方式不同；这些文件不要与整合订阅重复叠加。

| 旧包文件 | 真实作用与限制 |
|---|---|
| `Jimmy-Stash.yaml` | 旧离线基础主配置，内嵌分流与38条基础域名规则；它本身不含全部App HTTP动作。私人机场URL只能在设备填写 |
| `广告增强.stoverride` | 旧本地安装的专项合包，声明11份远程JS，仍需联网、设备可信CA与HTTP/MITM；当前整合订阅已经包含相应动作，不用导入它 |
| `扩展域名.stoverride` | 旧离线完整有序规则快照，含终止MATCH。不能把它当普通广告列表随意前插，也不能叠加到当前整合入口 |
| `按App单独开关/` | 旧目录名保留，各文件是来源模块的本地声明，脚本仍为远程URL；当前用户无需逐个导入或设置开关 |
| `诊断（临时）.stoverride` | 只用于隔离排查，不参加日常去广告；按[诊断步骤](ADBLOCKING.md#用固定日志判断运行到哪一步)使用后关闭 |
| `源码/` | 维护文件、来源快照、许可证和教程；不是需要逐项导入的内容 |

已在使用旧离线包时，保留现有可用组合。其主配置没有远程更新地址，静态规则和HTTP匹配声明不会因GitHub更新自动改变；脚本现改为URL引用，可按自身间隔联网更新。只更新脚本不能更新其它静态文件。机场代理集仍按24小时间隔尝试刷新，但把节点直接写入文件的私人快照不会自动获得新节点。

迁移到当前整合订阅时：先在设备备份旧配置、私人URL和地区选择；从原公共URL导入整合配置，关联已有私人覆写（若旧包直接保存URL，则仅在设备转入私人覆写），停用旧广告增强/扩展/单App覆写，保留可信CA并重新连接。不要删除旧备份，也不要上传含私人内容的配置。详见[订阅教程](SUBSCRIBE.md)。

旧离线安装中，广告组DIRECT只停止域名拦截，不能停止HTTP动作；合包需停用对应旧广告增强覆写。当前整合入口则用HTTP/MITM总开关暂停HTTP处理。出错时切回设备实际可用的备份，不通过关闭TLS验证或跨地区直连兜底掩盖问题。

所有脚本与规则保留各自MIT/GPL许可证，项目根许可证不重新授权第三方资源。此前`content`内嵌声明已有用户反馈的provider解析失败；当前生成包恢复URL脚本声明，不再是完整离线脚本包。手机导入、广告效果和正常业务仍需验收。自动签到继续暂停。更新频率的当前建议统一见[更新教程](UPDATES.md#建议更新频率)。
