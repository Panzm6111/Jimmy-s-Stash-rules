# 更新机制与日常使用

当前版本ROUTE-20261029.5。客户端直订兼容上游；只有必须过滤/转换的规则交给GitHub Actions。电脑不再需要承担日常同步，Windows旧任务已在云端验收后禁用，并按用户要求移除系统登记，XML备份保留（2026-10-29），实际状态以[PROGRESS](../PROGRESS.md)为准。

| 内容 | 执行位置和更新方式 |
|---|---|
| 国内、东方财富、TikTok功能/广告、通用海外、AI主集、社交、Adobe主集 | 客户端直接订阅MetaCubeX的meta分支，domain YAML，86400秒刷新 |
| YouTube、Instagram、Twitter、GitHub、Stash大广告集 | 客户端直接订阅blackmatrix7完整兼容classical YAML，86400秒刷新 |
| Clash基础去广告 | 直接订阅MetaCubeX category-ads；保留仅基础域名广告的范围 |
| Netflix、Telegram、TikTok、Apple、Microsoft | GitHub过滤既有PROCESS-NAME/IP-ASN后发布，保持两端原有基本规则语义，共5份转换 |
| Sukka AI补充 | GitHub转为classical YAML，保留旧URL正则遗漏记录，第6份转换 |
| 系统例外、App广告、HTTP/JS、自检与Adobe官方补充 | 项目固定审查源；有需求或证据时改动，未启用自动签到 |
| 策略组、规则顺序与主配置结构 | 原Stash主订阅；Clash Jimmy全自动主订阅1440分钟刷新 |
| 机场节点 | 设备本地私人provider，24小时尝试更新；Clash下载出口300秒主动检查 |

AI、社交和Adobe拆成相邻规则集，目标策略与匹配优先级不变。原21业务组、四地区ai、TikTok统一社交和Clash隐藏下载回退组不变。Stash27份、Clash自动入口25份规则集，其中每端17份直订；数量增加来自拆分，不是增加业务策略组。

云端工作流[必要规则云端更新](../.github/workflows/refresh-rules.yml)每天北京时间12:17计划运行，避开整点；也支持Actions页面Run workflow。每次只读取6份转换输入及许可，异常/大幅变化停止；有实际变化才构建、验证、精确提交和推送。验证在同一工作流内完成，失败不发布；GITHUB_TOKEN推送不另触发push CI，不需要私人PAT。无变化不提交。依赖固定SHA，write权限只给此发布作业。

GitHub定时执行可能延迟；公开仓库长期60天无活动可能停用schedule，需在Actions页面恢复。不能承诺每天精确到分钟。依据：[GitHub schedule说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

旧Windows脚本保留用于明确回退或人工排障，不再是推荐日常路径。旧本地Merge结构仍须换版本；使用完整远程主订阅才能自动取得新结构。私人订阅、节点和证书留在设备，不进入GitHub。

## 日常最少操作

1. 保留已能用的配置备份、本机私人订阅覆写与证书。已接入成功的不重填机场URL、不重建私人覆写、不重装证书。
2. 首次迁移或收到修复发布说明后，在配置列表刷新原公共URL；若曾另装App/广告增强/expanded/诊断覆写，停用这些额外广告条目，未装过直接跳过。私人订阅和必要的本机白名单保留。
3. 选中更新后的配置并重新连接，确认私人覆写仍关联、节点仍在、总代理及软件地区选择符合自己的设置。现行配置和脚本标记均为`AD-20261020.5`；本次补齐fmz200广告分支，43条原生动作、11份响应JS和1份自检JS；新增主机与handler范围必须随主配置一起更新。
4. 检查国内/海外连接和关注的广告场景。若规则集或机场下载失败，再单独刷新相应资源。不会以下载成功代替广告效果、正常业务或地区锁定验收。

开屏仍在时，直接用Safari打开[本机自检页](https://example.com/jimmy-stash-check)，开始15分钟诊断，使用App后返回结果页刷新。无需复制配置或另加覆写；用完停止，详细含义见[自检说明](ADBLOCKING.md#自检页排查)。版本参数只帮助区分新旧资源请求，不能保证断网或原生缓存异常时成功下载；页面版本不对或脚本下载报错时，只反馈版本和错误类别。

固定链接：

```text
https://raw.githubusercontent.com/Panzm6111/Jimmy-s-Stash-rules/main/config/stash.yaml
```

无远程更新地址的本地副本不会自动获得公共配置变化。迁移时从原URL导入，并在设备关联已有私人覆写；先备份直接写在旧文件中的私人URL，避免整份替换丢失。不把含私人信息的备份上传。完整安装见[订阅教程](SUBSCRIBE.md)。

## 每一层怎样更新

| 层 | 当前作用与保留边界 |
|---|---|
| 整合主配置`config/stash.yaml` | 分流、App动作、11份响应JS及1份自检JS的URL声明；唯一广告RULE-SET引用扩展包。刷新整份配置时不应承载私人URL的长期编辑 |
| 本机私人覆写 | 保存机场URL；不从公共地址更新。更新后核对关联与优先级，不能用普通YAML测试证明Stash保留了UI状态 |
| 远程代理集“机场” | 获取节点，不继承机场响应里的分流、DNS或软件策略组。节点改名可能使手选项或地区筛选失效 |
| 远程规则集 | 由有效RULE-SET引用后参与路由，局域网/关键系统例外和本机白名单保持优先。实际误拦仍需手机排查 |
| 本机临时诊断记录 | 仅手动开始后的15分钟内写固定状态、计数和时间；留在Stash设备存储，不随公共文件上传，不是账号凭据存储。新一轮仅展示当前轮次，停止或过期停止新增记录 |
| 本地维护工具 | 检查公开上游；普通规则在隔离副本验证后写回项目。只在运行时工作，不操作机场、证书或账号，也不自动发布 |
| 旧main.yaml＋core/App覆写 | 仅保留维护来源和已安装用户兼容；旧安装分别更新各文件，不能与整合入口重复叠加。当前需求不再包含逐App开关 |
| 旧离线ZIP/私人节点快照 | 静态规则与主机/handler变化要重新构建、导入；脚本改为远程URL，仍需联网。私人节点快照不自动获得机场新节点。原离线包说明见[兼容说明](LOCAL-IMPORT.md) |
| 自动签到 | 仅保留调查备忘，没有脚本、Cookie捕获或定时任务，不参与更新 |

## 常见问题

| 现象 | 处理顺序 |
|---|---|
| `provider: url,payload, path are all empty` | `.3`已移除11个仅含content的脚本来源声明并获用户导入恢复反馈。仍运行旧配置时刷新原公共主配置至当前`.5`并重连，保留私人覆写和证书；若继续失败只反馈版本标记及脱敏错误文字 |
| 不能访问网络 | 确认选中整合配置、私人覆写仍关联且机场已加载。总代理初始REJECT，首次须明确选择出口；失败可回到上次能用的备份 |
| 节点少或SS/VLESS连接失败 | 按[订阅兼容](SUBSCRIPTION.md)核对格式、数量、协议与脱敏错误；不静默删节点或关闭TLS验证 |
| 地区池空或全部失效 | 核对名称与成员；配置不加入其他国家或DIRECT后备，原生失败行为仍需验收。不要为连通自动换国家 |
| 延迟正常但服务不可用 | 测速不验证解锁、账号或风控；先在自己选定地区内核对节点 |
| 登录、消息、播放或正常券异常 | 先把广告组切DIRECT排查域名拦截；仍异常再关闭HTTP/MITM并重连。DIRECT不会停止HTTP动作 |
| 仍有广告 | 更新后用[自检页](ADBLOCKING.md#自检页排查)开始15分钟诊断，只反馈App、版本和固定状态；原生动作无响应JS记录，不能把页面空记录等同MITM失败。没有证据时不重装证书、不全局禁UDP |
| 更新后选择丢失 | 核对配置/组名和私人覆写关联，按自己设备记录重选。原生状态持久化尚未实测 |
| 公共资源下载失败 | 保留当前可用配置和资源，检查网络/报错；不把私人订阅发送到镜像或转换网站 |

DNS的`dot.pub / NotValidForName`、陌生`Google/NCloud`策略组等旧故障，按[运行中排障](SUBSCRIBE.md#已启动但打不开网页或出现dns证书错误)检查实际生效配置、DNS与覆写。始终保留TLS验证，不发送完整私人配置或日志。

## 暂停处理与回退

暂停域名拦截：广告组改DIRECT。暂停HTTP处理：关闭HTTP/MITM并重建连接。停止Stash则停止本项目接管；网络广告规则不能删除App已下载的缓存素材。整合模式不提供逐App开关，符合当前确认的使用要求；停用额外同名覆写不能撤销内置动作。

正常排查无需卸载证书。若完全不再使用MITM，可撤销自己CA的信任并移除描述文件；私钥不上传。出现无法恢复的问题，切回设备保存的上次实际可用配置并关联原私人覆写。

主配置回退只恢复当时的声明；远程JS和规则集若仍指向main，会继续读取当前资源，脚本URL上的`?v=...`也不把main固定为历史字节。完整版本回退需配套脚本及规则集版本，不能只换一个旧YAML就声称所有资源一起回退。旧content-only版本已有解析失败反馈，不作为本次推荐回退目标。

本地维护工具产生的规则更新可按[维护教程](MAINTENANCE.md)使用备份回退；已经发布的变化还需把回退结果重新提交到GitHub，手机才能通过原链接取得回退内容。其他手工修复需还原对应的源配置、规则、模块和脚本，运行`python tools/build_ads.py --write --bundle`，验证后提交到原main；稳定链接不变，不用破坏性重置清掉未保存修改。本机已设置每天12点任务；电脑和可用GitHub连接均是成功执行的条件。

## 私人信息误提交

如私人URL/token、节点凭据或证书确已公开，立即撤销或重置相应凭据，再按GitHub敏感数据处理流程清理历史。只删当前文件不能清除历史、缓存或fork。项目扫描只打印位置与模式，不能证明不存在所有未知凭据格式。
