# 更新、排障与回退

## 各类文件不是同一种更新

当前推荐[一体化公共订阅](SUBSCRIBE.md)：`config/stash.yaml`在AD-20261020.2包含公共分流、扩展广告规则集引用、已审查的40款App专项和11份内嵌响应脚本，本机私人覆写只保存机场URL。刷新同一配置URL会取得公共快照，不删除/重建本机覆写；仍须检查本机覆写的关联与优先级、地区选择和证书状态。直接在远程主配置里保存私人URL会在重新下载时有丢失风险，不能当作推荐做法。

另有[本地下载包](LOCAL-IMPORT.md)作为备选。它将规则展开为主配置中的静态规则，将11份广告JS（另有可选诊断）保存在script-providers.content；没有公共资源自动刷新。机场仍联网请求更新。以后更换本地主配置前，在设备备份、复制原订阅到新文件并记录/恢复地区选择；只更新广告增强不会改主配置中的订阅。下表同时区分推荐整合入口与备选分层模式；不用为了更新切换安装方式。

| 类别 | 获取/合并 | 更新触发与保留边界 |
|---|---|---|
| 本机主配置 `config/main.yaml` | 首次下载为本地文件导入，持有 provider 和基本 DNS；不假设 YAML 任意变量展开 | 本地文件不会因仓库更新自动重写。当前不需要跟着每次规则更新重导；如将来模板变更，按变更说明迁移并在本机保留私人 URL |
| 一体化远程主配置 `config/stash.yaml`（推荐） | Stash下载整个公共配置；分流、App动作及11份响应JS内嵌，默认引用扩展广告RULE-SET | 配置列表刷新同一URL即取得这些声明与脚本，无需另装App/expanded覆写。扩展规则集和机场仍各自联网更新。私人参数放本机覆写，更新后核对关联和选择；不把私人URL直接写进远程主配置 |
| 公共覆写 `config/core.stoverride` | 远程下载后与本地主配置合并，提供组和规则 | 在 Stash 的覆写管理刷新原条目并重新应用；**尚未核实自动检查/拉取行为，不能保证按 interval 自动更新覆写本身**。精确合并语义和原生选择保留待官方/手机验证 |
| 本机私人覆写 | 本地文件/本地编辑，映射字段覆盖“机场”的 url | 不从公共地址更新；不要删掉重建。公共 core 不含机场 URL；若未来 core 新增同名 provider，要先检查未覆盖本地层 |
| 远程代理集“机场” | 指向设备填写的 URL，不把机场的业务策略组当本项目组 | `interval=86400` 请求刷新，另可手动刷新；失败后保留旧缓存的确切行为待核实。节点名变更会影响手动选择和地区筛选 |
| 远程规则集 | 拉取本仓库 `rules/*.yaml` 的 classical payload；快照源版本固定 | `interval=86400`，也可手动刷新；只会获得本仓库主分支已发布的快照，上游自己更新不会自动改变本仓库快照 |
| 广告覆写（仅分层/本地包模式） | 扩展包替换现有广告provider的URL；各App专项定义域名规则、HTTP动作和handler，列表见[模块目录](AD-MODULES.md) | 通过覆写页面分别刷新/启停。推荐整合入口已包含这些功能，不叠加；停用额外覆写不能撤销主配置内置动作 |
| 广告 JavaScript | 推荐入口和本地包使用`script-providers.content`内嵌；分层App覆写引用稳定`.js` | 推荐入口随主配置更新，本地包需换包；分层远程JS才按provider interval=86400请求刷新。脚本不写任何存储，更新不清除App自己的缓存 |
| 自动签到备忘 | 仅研究文档与暂停状态 | 用户已暂停，不生成脚本、捕获器或 cron；不参与当前安装与更新 |

interval 是客户端尝试刷新间隔，不是断网仍能更新的保证。CDN 缓存可能延迟；不可把每个文件都认为“打开 App 自动最新”。除非你明确修改，后续一直使用同一主项目和稳定路径，不建立第二套“最新版/最终版”。

## 前次测速与海外AI调整的迁移

这次只更新原有主项目：原“全部节点”改名为“自动节点”，原OpenAI组改名为“海外AI”。自动节点、美国、日本、香港、新加坡、台湾和其他地区共7池改为原生 `url-test`，用 `https://www.gstatic.com/generate_204` 每1800秒检查，按最近成功HTTPS探测延迟选择最低者；具体切换阈值、缓存和时机未实测，不保证即时最快或服务解锁。“自动节点”可以跨国家，“其他地区”可以在它包含的多个国家间切换；五个单地区池仍不加入其他国家或DIRECT。手动指定全池中的节点，继续使用“手动节点”。

已经能正常连接的用户按自己当前的方式操作一次即可：

1. 在手机保留能用的配置，并记下总代理与各软件选择。**不要重填已能用的机场URL，也不要重建私人覆写。**
2. 一体化订阅用户，在配置列表刷新原 `config/stash.yaml` 公共主配置；core分层用户，在覆写管理刷新原 `config/core.stoverride` 并应用，再刷新海外AI规则集。规则文件仍沿用 `rules/openai.yaml` 稳定路径。
3. 核对新名称。若总代理此前选“全部节点”，旧名称消失后可能回到REJECT，应重选“自动节点”或自己需要的地区；原OpenAI的选择也需在“海外AI”中确认。
4. 核对“海外AI=美国”“Apple=DIRECT”，Microsoft默认仍DIRECT，其他软件默认总代理。它们是文件默认值，Stash可能保留旧UI选择，不能保证更新会强制改变。若需要其他选择，可自行修改。
5. 确认私人覆写仍关联、节点仍在，测试普通连接和所需AI服务。失败先切回设备保留的旧配置，不删除私人订阅。

如果正在用直接手改过的本地副本，先在设备备份私人URL与原文件，再取得更新后的公共配置并在本机恢复私人值；本地副本不保证拥有公共配置自动更新关系，也不能保证整份替换后保留手改内容。不要把含私人信息的备份上传。

## 日常最少操作

本次AD-20261020.2将原入口改为整合模式：**停用已另装的广告增强/App/expanded/诊断覆写（没装过就跳过），保留私人订阅覆写，刷新原主配置，确认版本并重连。** 不需要另外导入模块或更新11个远程JS。详见[去广告更新步骤](ADBLOCKING.md#已安装用户怎么更新)。

1. 先在本机记下每个软件选择的**组名**，如“总代理=日本，海外AI=美国”；不用发节点详情或截图。
2. 推荐整合订阅刷新原公共主配置；只有分层模式才分别刷新原core/App覆写和远程JS。远程规则集或机场下载报错时，在相应资源页面刷新原条目。
3. 查看最终配置，确认私人 URL 仍是本机值、所需组名还在、关键放行优先级没变；此次更名按上面的迁移说明处理。
4. 检查 UI 选择是否保留。若原生版本没有保留，照第 1 步重选；不假装 YAML 可以保存用户点击状态。
5. 验证一个国内服务、一个海外服务与选用的广告模块；确认无问题后继续日常使用。

为降低变更范围，主配置、私人覆写、地区组名和机场名称平时保持不动。重装 App、清数据、删除再导入配置或节点更名可能丢选择，备份只留在设备。

## 常见问题

| 现象 | 处理顺序 |
|---|---|
| 一开配置全部不能访问 | 总代理初始 REJECT 是有意设置；确认私人 provider 已成功加载，改选自动节点或自己需要的地区，保持规则模式；没有 core 时模板也会拒绝 |
| 地区池没有节点/一直拒绝，手动节点却可用 | 检查名称是否匹配、池成员和哨兵；暂停使用地区池并反馈真实 Stash 版本/错误类别。不删 REJECT、不加 DIRECT 或其他国家来“救活”严格池 |
| 订阅解析通过但节点少 | 对照机场数量与协议，按 SUBSCRIPTION 查格式/字段；不要悄悄抛弃 VLESS 后声称兼容 |
| 延迟正常，Netflix/OpenAI不可用 | 普通探测不验证地区解锁/风控/账号资格；在保持同地区前提下手动试同池节点，需自己确认后再改国家 |
| 国内站变慢或误走海外 | 看最近连接的域名/命中规则/目标组；检查手动放行和共享域名；扩展包沿用核心优先级，不应盖过系统例外；不要凭 App 名称猜规则 |
| GitHub Raw 下载失败 | 先确认公共文件确实已进 main；未发布时 404 正常。已发布后再查原生资源下载策略/网络环境，不发送真实订阅到镜像/转换站，不擅自关闭 TLS |
| 拦广告后登录/付款/券打不开 | 广告组切 DIRECT；若仍不行关 HTTP 广告覆写/MITM；定位误杀后窄域放行。付款保留手动，项目不自动购买/兑换 |
| 某个App仍有广告 | 确认主配置为AD-20261020.2、内嵌脚本/精确主机/handler存在、没有重复广告覆写；已有信任CA无需重装。App版本、缓存、协议和端点也可能不匹配，按固定诊断排查，不添加全局解密 |
| 更新后软件回到默认选择 | 检查组名是否变化、配置是否重建；按本机记录重选。当前没有在 iPhone 证明 UI 状态持久化 |

## 关闭模块与彻底回退

若日志显示已启动，但出现`dot.pub / NotValidForName`，或策略组出现本项目没有的Google/NCloud，先按[运行中排障](SUBSCRIBE.md#已启动但打不开网页或出现dns证书错误)核对正在使用的配置、覆写和界面DNS设置。这与YAML导入失败不同，不关闭TLS验证。剩余流量等提示项目也不是实际连接节点。

只关闭域名去广告：广告拦截组改DIRECT。推荐整合入口没有逐App开关，暂停HTTP处理需关闭HTTP/MITM并重连；停用额外App覆写不撤销内置动作。原分层模式才可停用对应软件覆写。若完全不再使用MITM，可撤销自己的CA信任并移除描述文件；一般排查无需卸载证书。

临时全恢复：停止 Stash，系统恢复正常网络路径；这同时停止依赖 Stash 的分流、去广告与未来调度。不要因此以为机场或服务已恢复，只是已绕过本项目规则处理。

继续用原机场但回退公共变更：在设备保留一份上次**实际验收过**的主配置和相关资源；出问题时切回该备份并关联原私人覆写，保持私人provider不动。整合配置回退会带回其内嵌脚本，但远程规则集仍指向main资源，完整回退还需同版本规则集备份。分层模式同样需要配套core/广告覆写/规则/JS，不假设只回退core就能带回全部资源。

维护者的完整历史回退：Git中还原指定公共提交的config/modules/rules/scripts，运行`python tools/build_subscription.py --write`、验证并提交到main。稳定链接不变，客户端刷新即可获得回退；源文件与一体化入口必须一致。不要reset --hard清掉未保存工作；实际已发布提交见PROGRESS，手机备份仍只留在设备。

## 私人信息误提交

立即撤销/重置相应订阅、token/登录会话或证书。仅删当前文件不能清除历史、缓存、fork；后续由仓库所有者按 GitHub 的敏感数据移除流程处理历史。项目扫描只输出位置和模式名，不打印命中值，但模式工具无法证明所有未知格式均不存在。
