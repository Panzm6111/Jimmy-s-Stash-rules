## 连接与负载

生产 Clash Verge 的命名管道只用于读取库存。Windows 上 `verge-mihomo.exe` 支持从标准输入读取配置；隔离实例只加载运行中确实出现的出口。其控制端和认证代理均使用随机回环端口。客户端选择、现有 TUN、路由、防火墙、原订阅和系统代理均由用户的原客户端管理。采集器通过 Windows Job Object 持有自己的内核。UI 和测量进程各自独立。物理上行接口从有默认路由的已连接物理网卡中识别；多接口无法唯一确认时会记录异常。

每 60 秒重读生产 Provider，并与客户端已安装的本地 Provider 缓存核对。包括滚动账户提示在内的所有可见名称须能在本地缓存找到，再逐出口核对协议、完整配置指纹与唯一身份。如果某个 Provider 的可见库存和缓存不匹配，记录 CONFIG_CHANGED，并继续按名称测量可匹配的已安装出口。2026-11-10 实测表明，另行下载的远端订阅可为相同名称返回不同 TLS 指纹。因此正式采集只使用客户端本地安装的内容。订阅正文和地址不进入监测库或输出日志。

Provider、名称、类型与完整原始节点配置参与带本地盐的 HMAC。名称或配置变化产生新身份。跨 Provider 同名会形成不同测量别名。重复、协议不一致、无法匹配及未支持的覆写会记录异常，安全匹配的其他出口可继续监测。经相同连接参数和多条账户提示交叉确认的流量、重置、到期标签从监测与排名排除。旧原始观测保留，仅通过排除表标明历史口径。当前界面默认只显示在用版本，可展开已退出版本。

本轮测量实例绑定 WLAN，IPv6 关闭，使用新建 HTTPS 请求。日用内核启用了 TUN、IPv6 及 unified-delay。报告描述这一台机器在指定测量条件下到各目标的表现；家庭 WLAN 改变、手机蜂窝网络、IPv6 专线路径等条件需另行测量。当前直连控制目标的访问同样绑定测量上行。生产命名管道不可用时只允许回退到运行配置明确指定的回环 TCP 控制端。

普通目标 5 秒。压力窗不选候选。两个目标在每个节点上轮换，每目标每秒最多 8 次调度。候选最多 10 个，并受目标请求预算限制。实际 56 个出口，普通 5 秒、候选 1 秒时预算可容纳 5 个候选；普通 10 秒、候选 1 秒最多可容纳 10 个。当前硬上限 30 个节点在途请求、36 个连接池位置，快采样最多占一半在途名额。每节点单飞，未知结束后额外冷却 3.25 秒。

## 数据解释与恢复

- **2026-11-13 指标更正：请求结局与责任归因分开。** `UNKNOWN_ERROR` 在旧规则中可能表示多个出口同步超时，无法把责任归于单节点；原始 `NODE_TIMEOUT/504` 和 `NODE_TEST_FAILED/503` 已给出失败结局，不能从实际请求成功率分母排除。报告新增独立的 `tools/stability_outcomes.py` 结局层：实际请求成功率为确认目标204成功 /（成功 + 内核明确超时 + 明确探测失败），无论责任是否明确都保留已知失败。控制接口不可测、204响应未确认、进程中断结局丢失以及在途各自单列。原始行、归因分类、评分和采集条件不改写；页面及原排名更名为“节点归因成功率”，不能当成实际连接成功率。新增结局层仅在明确请求报告时做分组读取，不增加采集器请求或每次页面刷新扫描。
- **覆盖的两种用途。** 原评分的“归因有效覆盖”不等于完成测量覆盖；完整回包但责任不明的失败仍证明完成过测量。按用户要求的在机分析，排除已确认没有发起请求的停采区间后，完成测量覆盖计入这些已知超时和失败；责任归因覆盖另外保留。当前临时线路比较采用实际请求结局，完整连续窗口和旧评分资格作为独立证据，不以旧归因资格否定已有访问样本。
- 采样时钟使用 monotonic。数据库保存 Unix UTC 秒（含小数），显示采用北京时区。每个实际请求的开始、结束、monotonic 总耗时、Mihomo 延迟、目标、间隔、原始判定和环境记录可通过 `st_sample`、`st_env`、`st_node` 关联。
- WAL、FULL 同步、采集器排他文件锁。先写入准入意图才允许网络发起。进程在意图写入与结果持久化之间被强杀时保留未知状态，记录崩溃恢复，完成时间、延迟不可恢复时保留空值。已返回结果先持久化，随后按十秒窗口复核同目标独立节点的成功、失败分布，最终记录和聚合在同一事务中提交。SQLite 独占写锁冲突时暂停准入；占用告警在 `.local/stability/writer-alert.txt`。进程异常位置写入同目录 `alert.txt`。低于 3 GiB 空间停止准入。
- API 失联、局域上行中断、目标异常和无法归因的同步故障单列。503/504 保留在原始记录中。归因窗口少于三个独立节点或半数以上节点同向失败时，缺少对照证据的失败进入 UNKNOWN_ERROR。孤立的节点探测失败也只表示该节点到该目标的请求失败。
- 原节点责任归因成功率的分母为归因后的 SUCCESS、NODE_TIMEOUT、NODE_TEST_FAILED；不是实际请求结局成功率。实际请求口径按上方独立结局层还原，将责任不明但已超时/失败的请求纳入失败分母。忙、容量、休眠、API、本机及目标事故继续单列。请求覆盖估计使用实际请求数除以按已知计划与各段日历时长积分的理论槽数，变更边界可能相差一个槽。原归因有效覆盖按可归因请求的计划间隔累计，完成测量覆盖则还计入结局已知的同步失败。界面同时显示最近完整自然分钟实际 Hz 和窗口内平均 Hz，聚合判定最多滞后约 17 秒。
- 评分参数位于 `tools/stability_stats.py` 的 `WEIGHTS`。70% 取两个目标中较低的成功率 Wilson 下界，25% 取有效覆盖，5% 取较差目标 P95 的延迟分（0–3000 ms 线性）。下界按各频率所代表的时间加权，有效样本数最多折合每五秒一次。每个目标至少 50 个有效样本、下界至少 90%，且身份存续期、所选时段的全窗口有效覆盖均至少 75%。序列相关性限制置信解释。候选每十分钟评估一次，现有候选保留 1.5 分的滞回。最后的综合榜还要求三个时段均达到门槛。
- 实时页面分位数是成功样本直方图的分桶上界。最终 HTML 分目标计算成功样本的最近秩 P50/P95/P99、四分位距、失败段数、最长连续失败观测次数与跨度。缺口、中间不确定事件会截断失败段。分目标数据和归因前状态留在同库。扫描原始历史仅用于明确请求报告或阶段结束。
- 单机 venv 在原有 PyYAML 基础上使用 `aiohttp==3.14.5`、`psutil==7.2.2`。正式运行前需能访问本机生产控制器、运行用户能读取已缓存订阅。运行数据、报告、诊断均在忽略的 `.local` 中。
