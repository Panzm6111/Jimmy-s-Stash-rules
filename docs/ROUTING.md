# 分流与地区节点池

## 当前分流与测速（ROUTE-20261112.1）

Stash 和 Clash 各有 23 个策略组，其中 10 个为自动测速池。Clash 另有 1 个下载回退组。两端分别加载 36、33 个规则集，分别有 26、25 个直订上游，两端合计 27 个独立上游地址。

三个精选池均配置每 60 秒主动测速。Stash 关闭这三个池的惰性测速，其他七池沿用 1800 秒。Clash 的机场健康检查从 300 秒缩短到 60 秒，超时 5 秒，要求 HTTP 204。容差表示当前健康节点与候选节点的延迟差，单位为毫秒。 Mihomo 中已固定的池应解除图钉。旧连接可能需要应用发起重连。

手机补充采用秋风 Only.Ads 整集，排在全部既有分流和 `GEOIP,CN,DIRECT` 之后、`MATCH` 之前。命中原规则的请求仍按原策略处理；即使因此保留部分广告，也不提高新广告集的优先级。仅 Stash 接入，Clash 使用基础域名广告集。详见[去广告边界](ADBLOCKING.md#手机补充与现有规则优先级2026-11-02)。

优先级为系统例外 → Stash路径例外 → TikTok广告/专属功能 → Stash明确App广告 → 小红书/抖音/东方财富及国内游戏DIRECT保护 → Adobe → 通用广告 → AI/各平台 → 腾讯DIRECT及国内总分类 → 海外社交补充/通用代理 → 中国IP直连 → Stash手机广告补充 → 兜底。小红书、抖音采用MetaCubeX整份分类，抖音另直订blackmatrix7整份DouYin分类，包含与旧TikTok补充冲突的snssdk.com。专属TikTok分类更早匹配；同一共享主机的不同App用途无法单凭域名区分，这里明确优先国内分类。代价是这些完整国内分类内的部分追踪/广告域名会直连，不做本地删选域名的第二套名单。

评论检查覆盖小红书web评论/子评论、抖音web评论/回复和代表性移动API主机、TikTokweb评论/代表性地区API、东方财富股吧/代表性API，以及其他常见国内外服务。111个测试样例见[app-routes.json](../tests/fixtures/app-routes.json)，两端共222项；重点评论URL还检查没有被Stash现有rewrite/script匹配。样例是回归输入，不生成手写运行规则。验证正常分流不等于在iPhone上实际加载、翻页、发送评论成功，也不能证明评论IP属地显示；没有抓取账号、发表评论或保存评论内容。

以下说明中的共用池、名称过滤和原生边界继续适用；旧迁移部分只记录历史。当前每端只保留一个主订阅，主配置自动更新，电脑每日任务已移除。

## 国内游戏直连（2026-11-02）

已确认：国内游戏尤其王者荣耀不经代理；明确海外游戏平台保留原分流，难以区分的游戏共用服务按用户补充要求直连。接入MetaCubeX三份完整维护分类：[国内游戏](https://github.com/MetaCubeX/meta-rules-dat/blob/meta/geo/geosite/category-games-cn.yaml)、[国服/国内平台标签](https://github.com/MetaCubeX/meta-rules-dat/blob/meta/geo/geosite/category-games%40cn.yaml)、[腾讯共用服务](https://github.com/MetaCubeX/meta-rules-dat/blob/meta/geo/geosite/tencent.yaml)，审查快照分别263/37/686条，客户端每24小时更新，纳入每日上游健康检查。没有自建游戏域名或IP清单。

国内游戏两集在通用广告前使用固定DIRECT；腾讯整份分类在通用广告和AI/Adobe等专用业务后、国内总分类前使用DIRECT，覆盖qq.com等王者官网、游戏SDK及资源域名。它包含QQ/微信、共享CDN等其他腾讯服务，也含部分跨区游戏基础服务，这些匹配项一并直连；明确广告仍由更早的广告规则处理。原神/星穹铁道/绝区零、WeGame、完美世界、西山居等按上游分类直连。海外Steam商店/社区、Epic、EA、Ubisoft、战网、Riot及HoYoverse样例保持原总代理路径；没有把全球Game合集整体改为直连。

中国IP的最后兜底改为`GEOIP,CN,DIRECT`，不经过可手动选择代理的“国内直连”组，兼顾没有域名的IPv4/IPv6游戏连接；更早的专用域名规则仍优先。不是所有UDP直连，也没有按猜测端口或整个腾讯云IP段放行。不改节点、策略组、DNS、HTTP改写或MITM配置。

这些规则在**规则模式**生效；全局模式会跳过业务分流。DIRECT表示不经过远端代理节点，游戏流量仍可能经过本机VPN/TUN处理，不等于应用级排除VPN，也不保证降低多少毫秒。王者真实登录/匹配/语音/整局延迟及丢包尚未验收；当前域名回归和中国IP分类输入均不能冒充手机抓包或真实对战。

## 软件选择的是池

海外AI 默认选 ai（新加坡 A、荷兰、英国 B，250 ms）。TikTok 默认选 AI最速（这三条加日本 A/B、美国 C/D，100 ms）。总代理默认选最速节点（HKG A/B/C/I/J/M、日本 A/B、荷兰、新加坡 A、英国 B，50 ms）。

业务选择器保留 ai 和手动选择入口。TikTok、Instagram、X 共用 TikTok 组。

Netflix、YouTube、Telegram、Adobe 和未匹配流量默认跟随总代理。Apple、Microsoft、国内直连默认 DIRECT，广告拦截默认 REJECT。已有设备会记住手选结果，刷新主订阅后请核对这三个业务入口。

“自动节点”包含全机场连接候选，不按国家分组，由原生 `url-test` 选择最低探测延迟；它可能跨国家切换。需要查看和手选全池节点时，使用保留的“手动节点”select组。Stash仍可在软件组直接手选；Clash的多个业务使用“手动节点”时会共享手选结果。

“其他地区”按常见其他国家和地区的中文、英文、缩写、旗帜正向匹配，例如韩国、英国、德国、加拿大、澳大利亚等，**不是五个地区的严格补集**。此池也改为自动选最低探测延迟，可能在其中的不同国家之间切换，不能当作固定国家池。无法按名称归类或未收录的节点仍在“自动节点”和“手动节点”中；不要据名字猜测真实出口。

“自动节点”“手动节点”及软件内平铺列表会过滤名称以“剩余流量、流量剩余、到期时间、套餐到期”等常见提示前缀开头的条目；不会改写订阅响应，也不按SS/VLESS协议删节点。未知提示名、加了其他前缀的提示仍可能出现，不能据列表存在就当作真节点。真实节点若恰好以提示前缀命名，可在手机临时副本移除对应组的filter核对，或请机场改名。

提示前缀列表和无负向前瞻的生成器位于 `tools/generate_node_filters.py`，生成后仍使用原生 `filter` 字段。它只使用锚点、字符类和或分支，不假设Stash支持exclude-filter、负向前瞻或反向引用；原生结果仍需手机验收。

## 自动测速与地区范围

精选池按完整节点名称筛选；机场改名后请核对成员。常规地区池仍按地区规则筛选。Stash 同一节点在多个池共享健康结果。

与以前优先按顺序选可用节点的fallback方式不同，本次按用户要求改用最低探测延迟模式。周期检查之间网络状态可能改变，已建立的连接也不保证立即迁移。全池可跨国家、其他地区可在其多国候选内切换；需要固定国家时选择五个单地区池之一，或手选已确认出口的节点。

五个单地区池按名字正则筛选；中文、常见英文、US/JP/HK/HKG/SG/TW、数字后缀和旗帜都纳入结构测试。例如US01、United States、洛杉矶、🇺🇸；香港同时支持HK、HKG、hkg、HKG01等命名，缩写不区分大小写。不把Russia/Australia/BUSINESS的字符片段当美国，也不把South America/Latin America/North America这些洲级名称当美国。命名含两个地区（如“香港转美国”）可能同时命中，**名称筛选不是出口定位**，要按机场真实出口验收。

每个单地区组只有“对应地区筛选后的provider节点＋REJECT”，没有其他地区或DIRECT。filter包含 `^REJECT$`，目的是保留拒绝哨兵。**这证明配置意图，不证明Stash原生url-test在空池或全部失败时一定拒绝。** 官方文档复核和手机的空池/全失效测试完成前，不作严格出口保证；异常时先停止使用该池，不自动改去其他地区或直连。

本地私人文件合成工具生成固定节点快照时，空地区直接生成为仅含REJECT的select组，非空地区使用url-test。“其他地区”在该快照中为五地区之外的真实补集，这与公共provider的常见名称正向筛选有区别；它仍可能包含多个国家。

| 情况 | 项目期望 | 你需要检查 |
|---|---|---|
| 该地区没有节点 | 留下REJECT，拒绝访问 | 在手机预览和连接测试确认没有隐式DIRECT；若出现意外出口，停用并反馈 |
| 该地区节点全失效 | 仍拒绝，不跨地区 | 原生行为待测；不能为了能上网自动改另一国，需本人明确重选 |
| 一个同地区节点失败 | 在同地区其余可用节点中选最低探测延迟者 | 探测和既有连接状态可能滞后；普通探测成功不等于解锁 |
| 订阅更新失败 | 有确认有效的旧缓存时继续使用；无缓存则停止 | Stash实际缓存策略待核实，不承诺缓存必存活 |
| 节点改名或消失 | 地区重新筛选、手动项重新核对 | 检查所选地区仍有节点；手动项失效则自行重选 |
| 公共配置更新 | 尽量沿用已有UI选择 | 原生持久化不是YAML功能；此前组名变更按下节迁移，不能保证重装或清数据后保留 |

## 规则顺序与覆盖边界

整合入口的顺序是：本机手动放行（若有）→局域网与关键系统直连例外→两条HTTP路径处理所需的精确直连例外→专项广告域名→扩展广告规则集→海外AI/Netflix/YouTube/Telegram→Apple/Microsoft特定域名→国内常用域名→GeoIP CN→未匹配流量。

“海外AI”覆盖常用海外AI服务的已列明域名，包括原OpenAI范围；不能穷尽所有非中国AI，也不是识别App所属国家。详细服务、来源和遗漏见[海外AI覆盖说明](AI-COVERAGE.md)。不把整个google.com、microsoft.com、github.com或共享CDN全都划进AI组，未列入的依赖按后续规则处理。AI相关规则先于通用Microsoft分类，指定登录直连例外仍保持原优先级。

整合入口默认引用扩展广告包，provider沿用“基础广告”名称；不需要另装expanded。`flowplus.meituan.net`与`bootpreload.uve.weibo.com`两条精确直连例外让已审阅的HTTP路径处理有机会执行，避免扩展包整域拦截与它们竞争。本机放行保持最高优先级。HTTP动作不受“广告拦截→DIRECT”单独控制。

Apple：APNs、iCloud、证书状态与部分系统更新精确域名直接直连；其他纳入Apple列表的服务交给Apple组，默认仍DIRECT。Microsoft：Windows Update、下载与两个登录域名先直连；除更早命中AI规则的目标外，Office/OneDrive/Xbox/Bing/GitHub等列表中的域名交给Microsoft组，默认DIRECT。不会将整个Apple/Microsoft IP范围粗暴代理，也不保证列表覆盖它们所有产品。

国内常用域名采用有来源的China快照，不把所有.cn以外的网站都当海外，也不依靠IP地理库识别某个App。**这些是域名/IP规则，不是完整App身份识别。** 同一个App可能调用共享CDN、第三方登录/支付、直连IP、HTTP/3或加密DNS；规则不能保证覆盖每条连接。Apple的直连例外也不会因为改Apple组而自动跟随该组。

## 白名单与误分流

用 Stash 最近连接记录找到**具体目标域名、命中规则和策略**，先确认规则是否真的匹配。不要发整个记录或账号请求头。

下载 [本机手动放行模板](../examples/private-allowlist.stoverride) 到设备，把示例域名改为误杀的精确域名。只放行确认必要的一条，保持规则优先于广告；需要改去代理时将目标改为“总代理”或相应软件组。域名级放行不能绕过仍启用的响应脚本，排查HTTP误伤时关闭HTTP/MITM并重建连接，必要时切回设备可用备份。当前需求不再包含逐App开关。

测试模型覆盖代表性目标、误杀放行，以及扩展包错误包含局域网/指定系统服务时的优先级；这些只是结构与规则优先级证据，不是 DNS、IP 库、实际 App 流量或真实出口的实测。

更新建议：广告规则集和机场节点每24小时尝试刷新；主配置开启自动更新，修复发布后可立即刷新。30分钟测速不是规则更新。完整机制见[更新教程](UPDATES.md#建议更新频率)。
