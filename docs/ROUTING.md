# 分流与地区节点池

## 软件选择的是池

OpenAI/Netflix/YouTube/Telegram 等组是 `select`，候选为“总代理、美国、日本、香港、新加坡、台湾、手动节点、DIRECT”。各软件组还通过 use 展示机场的具体节点，可独立手选节点；“手动节点”则是供你主动选择跟随的共享入口。默认跟随总代理；总代理默认 REJECT，第一次必须由你自行选出口。Apple/Microsoft 默认 DIRECT，这是优先保持正常系统业务的中立初始选择。

地区池是 `fallback`，引用同一个“机场”provider，按地区名称正则筛选；中文、常见英文、US/JP/HK/SG/TW、数字后缀和旗帜都纳入测试。例：US01、United States、洛杉矶、🇺🇸；不把 Russia/Australia/BUSINESS 的字符片段当美国，也不把 South America/Latin America/North America 这些洲级名称当成美国。

地区组名和软件组名均保持稳定。公共更新只更新同一路径；节点改名不应导致软件改去别的国家，但可能失去手动节点选择或改变池成员。命名含两个地区（如“香港转美国”）会同时命中，**名称筛选不是出口定位**。请用机场的真实出口信息验收；不能用正则猜测。

## 为什么故障切换优先

- 故障切换依次使用可用候选，通常更利于固定出口；池内恢复、更名、订阅顺序变化、连接重建仍可能改变出口，不能保证绝对不换。
- 最低延迟 url-test 会按测试结果挑节点；即使带容差，也不同于服务解锁检测。本项目不启用该模式，不因轻微延迟变化主动追逐最快节点。
- 健康检查用普通 HTTPS 204 地址，30 分钟间隔，不是 Netflix、OpenAI 或 Telegram 的业务验证。该测试地址被屏蔽也可能让健康判断错误。

每个地区组只有“对应地区筛选后的 provider 节点＋REJECT”，没有其他地区或 DIRECT。filter 包含 `^REJECT$`，目的是无论静态节点是否参与过滤都不删掉拒绝哨兵。**这证明配置意图，不证明 Stash 原生 fallback 的内部行为。** 官方文档复核和手机的空池/全失败测试完成前，不作严格出口保证。

| 情况 | 项目期望 | 你需要检查 |
|---|---|---|
| 该地区没有节点 | 留下 REJECT，拒绝访问 | 手机预览/连接测试确认没有隐式 DIRECT。若发生直连或其他出口，停用此候选配置并反馈 |
| 该地区节点全失效 | 仍拒绝，不跨地区 | 不能为了“能上网”自动选择另一国；你需明确重选才改变地区 |
| 一个同地区节点失败 | 下一个同地区可用节点 | 既有连接可能需重建；普通探测成功不等于解锁 |
| 更新失败 | 保留能确认仍有效的旧缓存；无缓存则停止 | Stash 真实缓存策略待文档/设备验证；绝不拿空响应覆盖，也不承诺缓存必存活 |
| 节点改名/消失 | 地区重新筛选、手动项重新核对 | 先检查所选地区还有节点；手动项不存在则自己重新选，不暗改出口 |
| 公共覆写更新 | 固定组名，优先沿用 UI 选择 | 原生选择持久化并非 YAML 功能；更新后核对，不能保证重装/删配置/清数据后保留 |

## 规则顺序与覆盖边界

基础顺序是：本机手动放行（若有）→ 局域网与关键系统直连例外 → 基础广告 → OpenAI/Netflix/YouTube/Telegram → Apple/Microsoft 特定域名 → 国内常用域名 → GeoIP CN → 未匹配流量。

扩展广告是可选覆写，只替换原“基础广告”provider 的来源，不插入新的广告规则；因此仍位于局域网与关键服务例外之后、一般软件和国内规则之前。本机放行保持最高优先级。脚本属于 HTTP 匹配阶段，不受“广告拦截→DIRECT”单独控制。

Apple：APNs、iCloud、证书状态与部分系统更新精确域名直接直连；其他纳入 Apple 域名列表的服务交给 Apple 组，初始仍 DIRECT。Microsoft：Windows Update、下载与两个登录域名先直连；Office/OneDrive/Xbox/Bing/GitHub 等列表中的域名交给 Microsoft 组，初始 DIRECT。不是将整个 Apple/Microsoft IP 范围粗暴代理，也不保证这些域名包含它们所有产品。

国内常用域名采用有来源的 China 快照，不把所有 `.cn` 以外网站都当海外，也不依靠 IP 地理库识别某个 App。直连仍经过系统网络与服务商；不代表无隐私风险或一定可访问。

**这些是域名/IP 规则，不是完整 App 身份识别。** 同一个 App 可能调用共享 CDN、第三方登录/支付、直连 IP、HTTP/3 或加密 DNS；规则不能保证覆盖每一条连接。OpenAI 列表刻意不把整个 auth0.com、algolia.net 等共享服务泛化归为 OpenAI；未列入的依赖会落到后续规则。Apple 的直连例外也不会因为你改 Apple 组而自动跟随该组。

## 白名单与误分流

用 Stash 最近连接记录找到**具体目标域名、命中规则和策略**，先确认规则是否真的匹配。不要发整个记录或账号请求头。

下载 [本机手动放行模板](../examples/private-allowlist.stoverride) 到设备，把示例域名改为误杀的精确域名。只放行确认必要的一条，保持规则优先于广告；需要改去代理时将目标改为“总代理”或相应软件组。域名级放行不能绕过仍启用的响应脚本，脚本误伤应关对应广告覆写。

测试模型覆盖 23 个代表目标、误杀放行，以及扩展包错误包含局域网/指定系统服务时的优先级；这些只是结构与规则优先级证据，不是 DNS、IP 库、实际 App 流量或真实出口的实测。
