# 去广告使用、迁移和排查

当前修订 **AD-20261020.1** 已实际修改配置与脚本。保留原40款专项范围；具体处理链、来源与未覆盖部分见[详细规格](AD-ARCHITECTURE.md)。没有iPhone效果验收，不能说淘宝/微博开屏已经实测去掉。自动签到继续暂停。

## 已安装用户怎么更新

1. 在设备保留原可用配置、私人订阅覆写和地区选择，**不重填机场URL、不重建私人覆写**。
2. 在配置列表刷新原`config/stash.yaml`链接，选中它。检查编辑预览注释有`AD-20261020.1`；原18个策略组和私人“机场”provider保留，主配置现不内置HTTP专项。
3. 关闭旧整合“广告增强”和同款旧副本。从[模块目录](AD-MODULES.md)添加/刷新需要的App覆写并关联这份配置。建议先验淘宝、微博、小红书，再美团、京东，然后其他原专项。一款只启用一份。
4. 刷新这些覆写的远程JS，并重建Stash连接。**新增主机、原生动作和handler在覆写里，单刷新JS不够。** 用户已有完全信任的自建CA可沿用，HTTP/MITM保持开启。
5. 在最终预览确认：通用广告有一次`RULE-SET,基础广告,广告拦截`且在普通国内分流/MATCH之前；App规则与handler来自启用的模块；没有旧`http.rewrite`或共享空响应provider残留，没有同一路径重复handler。
6. 选中配置、私人关联、总代理/软件地区选择都核对后，按[手机验收](PHONE-CHECKLIST.md)多场景测试。

这次为了真实逐App开关，主入口拆出了内置HTTP。**仅刷新主配置、却没有启用App覆写，将只剩通用域名去广告。** 稳定地址和原文件均未另建版本。

## 基础与扩展域名

默认38条基础规则，有真实provider和RULE-SET引用，不需证书。可选[expanded](../modules/ads/expanded.stoverride)现在对原公共主配置和core都有效：把同一个provider替换成38,066条快照，保留系统/局域网白名单优先级；不是把整份含MATCH的配置前插。多规则不等于开屏有效，扩展可能误伤登录/优惠券，首次可先关闭。

私人手动放行示例只在设备使用：

```yaml
name: 本机手动放行
rules:
  - DOMAIN,confirmed-business.example.invalid,DIRECT
```

将示例主机替换成实际确认误拦的精确业务主机，放在广告RULE-SET之前；不把整个淘宝/微博网关放行当作HTTP脚本开关。

## 证书、模块与开关的关系

域名规则只看连接目的，不需要解密。HTTP URL重写/响应脚本处理HTTPS时需要精确MITM主机和设备自建可信CA；CA只提供解密能力，不包含去广告规则。脚本只改已知路径，但解密范围是列出的整个主机；不添加通配支付/银行解密。

首次需要证书时，在Stash生成自己的CA并安装，iOS“设置→通用→关于本机→证书信任设置”开启完全信任，再设置HTTP/MITM。已经完成的不重复重装。私钥不进入GitHub、日志或聊天。不通过关闭TLS验证解决问题。

- 关闭某App专项：关闭对应App覆写并重建连接。通用广告或另一模块仍可能影响同域名，另做精确白名单对照。
- 关闭域名拦截：广告组切DIRECT。**不会停止HTTP重写/脚本。**
- 暂停全部HTTP处理：停用App覆写和临时探针，按Stash界面关闭HTTP/MITM；通用域名规则仍可工作。
- 只需整包总开关：本地包可选广告增强，不和单App模块混装；合包没有逐款开关。

## 用固定日志判断运行到哪一步

默认不记录脚本日志。临时在目标App覆写的响应handler里将`argument: diagnostic=0`改为`argument: diagnostic=1`。若要创建临时副本，先暂停原件，只开诊断副本；排查后恢复远程原件并停掉副本。

日志形如`[JimmyAds][taobao][AD-20261020.1] changed`，仅模块、版本、固定状态。`body-unavailable`、`non-json`、`parse-error`、`unsupported-schema`、`unchanged`、`changed`和`exception`分别有不同意义，详见[决策表](AD-ARCHITECTURE.md#6-临时只读诊断先确定请求有没有进入引擎)。不打印完整URL、查询、Cookie、Authorization、账号值或正文。

如果根本没有命中证据，可临时使用[只读探针](../modules/diagnostics/ads.stoverride)：暂停App专项，独立启用，观察请求进入引擎后是URL命中还是未命中；使用完关闭，再恢复正式模块。不能拿无日志直接判定没进MITM，也不把probe的命中当作广告已去除。原生拒绝动作没有响应JS日志，要看Stash本机重写命中。原生超时看Stash自身执行记录，JS被终止后无法再自行记录。

## 当前边界与恢复

淘宝通用cloudvideo与poplayer未泛化启用，独立天猫App未有可靠专项；微博未声称覆盖全部首页信息流；小红书仅明确赞助项，不删普通带货笔记；美团新增仍为外卖链路，不代表主App完整覆盖；京东正文内functionId或加密新结构未获证据。其余完整范围见[逐款表](AD-MODULES.md)。

HTTP/3当前不进入改写引擎；本轮未观察真实QUIC，因此不默认禁UDP、不凭h3主机名下结论。不强制全域解密、不关TLS验证。预加载或缓存广告可能不发新请求；先用App自带清缓存入口，不默认卸载。

每款多轮检查冷启动、后台返回、预载后再启动，记录广告、空白、倒计时和加载变化；同时测登录/搜索/消息/视频/正常领券。单次无广告不算通过。误伤先关对应模块，域名问题再关expanded或设白名单；仍异常可切回设备上实际能用的备份，私人信息只保存在设备。
