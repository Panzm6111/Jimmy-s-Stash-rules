# 去广告使用、迁移和排查

当前主配置修订 **AD-20261020.2** 将使用方式统一为刷新原配置链接；广告处理脚本仍为 **AD-20261020.1**，并内嵌在主配置中。已审查的原40款专项范围保留，具体处理链、来源与未覆盖部分见[详细规格](AD-ARCHITECTURE.md)。没有iPhone效果验收，不能说淘宝/微博开屏已经实测去掉。自动签到继续暂停。

## 已安装用户怎么更新

1. 保留已能用的配置备份、原本机私人订阅覆写和地区选择，**不重填机场URL、不重建私人覆写、不重装证书**。
2. 如果另装过“广告增强”、单独App广告覆写、expanded或临时诊断覆写，先停用这些额外广告条目，避免重复挂载。没装过就跳过；保留私人订阅覆写。
3. 在配置列表刷新原`config/stash.yaml`链接，选中它。配置文本开头应有`AD-20261020.2`；原18个策略组、DNS和私人“机场”provider保留，App专项和响应脚本现已整合在主配置里。
4. HTTP/MITM保持开启，沿用已有完全信任的自建CA，断开并重新连接Stash。核对节点、地区选择和私人覆写关联。
5. 按[手机验收](PHONE-CHECKLIST.md)多轮测试冷启动、后台返回、触发预加载后再启动，同时检查登录、搜索、消息、视频和正常领券。

**日常只更新同一个公共主配置。** 无需再逐款添加广告覆写、找所谓App开关或导入expanded。新增主机、原生动作、handler和11份内嵌脚本随主配置一起更新；扩展域名规则由主配置中的远程规则集引用获取。

开发检查：最终配置应有一次`RULE-SET,基础广告,广告拦截`，provider URL指向`rules/vendor/ads-expanded.yaml`；保留局域网/系统例外优先级。主配置包含`http.url-rewrite`、响应handler及内嵌脚本，没有旧`http.rewrite`或共享空响应provider。结构正确仍不等于Stash真机执行通过。

## 基础与扩展域名

推荐入口现在默认引用38,066条扩展广告快照，不需证书；“基础广告”只是保留的provider名称。用户不用另行启用expanded。扩展规则集有真实RULE-SET引用，不是把整份含MATCH的配置前插。更多规则可能增加误拦，不能代替开屏接口处理，也不证明效果。

38条基础包仍供原`main.yaml + core.stoverride`分层方式使用。该模式下`expanded.stoverride`才是可选导入条目，关闭它恢复基础包。推荐整合模式停用额外expanded不会切回基础包，因为扩展来源已经在主配置中。

私人手动放行示例只在设备使用：

```yaml
name: 本机手动放行
rules:
  - DOMAIN,confirmed-business.example.invalid,DIRECT
```

将示例主机替换成实际确认误拦的精确业务主机，放在广告RULE-SET之前；不把整个淘宝/微博网关放行当作HTTP脚本开关。

## 证书、模块与开关的关系

域名规则只看连接目的，不需要解密。HTTP URL重写/响应脚本处理HTTPS时需要精确MITM主机和设备自建可信CA；CA只提供解密能力，不包含去广告规则。脚本只改已知路径，但解密范围是列出的整个主机；不添加通配支付/银行解密。

首次需要证书时，在Stash生成自己的CA并安装，iOS“设置→通用→关于本机→证书信任设置”开启完全信任，再设置HTTP/MITM。已经完成的不重复重装。私钥不进入GitHub、日志或聊天。不通过关闭TLS验证解决问题。

- 推荐整合模式：没有逐App开关，不要求安装App覆写。关闭额外同名覆写不能撤销主配置内置处理。
- 原分层模式：自行导入App覆写后，其条目的启停才是对应专项开关。关闭后，通用广告或另一模块仍可能影响同域名。
- 关闭域名拦截：广告组切DIRECT。**不会停止HTTP重写/脚本。**
- 暂停全部HTTP处理：在Stash界面关闭HTTP/MITM并重建连接；域名规则仍可工作。恢复时重新开启，不必重新安装证书。
- 本地下载包可选整合广告增强，仅有总开关；它与单App模式、推荐整合主配置互斥。

## 用固定日志判断运行到哪一步

默认不记录脚本日志。推荐整合模式需诊断时，在设备创建临时本地副本，仅将目标App响应handler的`argument: diagnostic=0`改成`argument: diagnostic=1`，保留私人覆写关联。排查后切回原远程配置、删除临时副本；不要把含私人内容的副本上传。分层模式才是在对应App覆写中做同样临时修改。

日志形如`[JimmyAds][taobao][AD-20261020.1] changed`，仅模块、脚本版本、固定状态。主配置为AD-20261020.2而脚本为AD-20261020.1是本次正常组合，未另改脚本逻辑。`body-unavailable`、`non-json`、`parse-error`、`unsupported-schema`、`unchanged`、`changed`和`exception`分别有不同意义，详见[决策表](AD-ARCHITECTURE.md#6-临时只读诊断先确定请求有没有进入引擎)。不打印完整URL、查询、Cookie、Authorization、账号值或正文。

[只读探针](../modules/diagnostics/ads.stoverride)必须在正式HTTP动作停止后单独使用。分层模式可暂停App覆写；整合模式仅停用额外覆写不够，需要在临时本地副本把`http.url-rewrite`和`http.script`清空，保留精确MITM设置，并将广告组切DIRECT后再启用探针。仅在需要定位时操作，日常无需导入；观察后关闭探针并切回原远程配置、恢复广告组选择。不能拿无日志直接判定没进MITM，也不把probe命中当作广告已去除。原生拒绝动作没有响应JS日志，要看Stash本机重写命中；原生超时看Stash自身执行记录。

## 当前边界与恢复

淘宝通用cloudvideo与poplayer未泛化启用，独立天猫App未有可靠专项；微博未声称覆盖全部首页信息流；小红书仅明确赞助项，不删普通带货笔记；美团新增仍为外卖链路，不代表主App完整覆盖；京东正文内functionId或加密新结构未获证据。其余完整范围见[逐款表](AD-MODULES.md)。

HTTP/3当前不进入改写引擎；本轮未观察真实QUIC，因此不默认禁UDP、不凭h3主机名下结论。不强制全域解密、不关TLS验证。预加载或缓存广告可能不发新请求；先用App自带清缓存入口，不默认卸载。

每款多轮检查冷启动、后台返回、预载后再启动，记录广告、空白、倒计时和加载变化；同时测登录/搜索/消息/视频/正常领券。单次无广告不算通过。误伤先将广告组切DIRECT排查域名，再关闭HTTP/MITM排查改写；仍异常可切回设备上实际能用的备份，私人信息只保存在设备。需要长期逐App启停时再选择分层方式，不要求普通使用者为此重装。
