# 粘贴链接导入Stash

当前统一使用这一条固定公共配置链接：

```text
https://raw.githubusercontent.com/Panzm6111/Jimmy-s-Stash-rules/main/config/stash.yaml
```

当前需求为整合入口，不需要逐App独立开关；这项已按用户决定调整，不再列为待开发功能。它保留18个策略组、7个自动测速池、手动全节点组、私人订阅接入、DNS和分流。**AD-20261020.5保留已审查的40款App专项和11份响应脚本，保留1份手动自检脚本并补齐fmz200广告分支，默认引用扩展广告域名规则集。** 已经能正常连接的用户，只需按下文刷新原主配置；不需要逐个导入App覆写或expanded，不使用订阅转换网站。

`provider: url,payload, path are all empty`已在`.3`修复，用户确认可导入；若仍运行旧版，按[简明更新步骤](QUICKSTART.md)刷新原链接并重连。用户随后反馈开屏仍在，`.4`增加诊断以定位执行环节，没有把广告效果认定为已修复。原私人机场覆写与证书继续使用。

## 第一次使用

1. 保留原来能用的配置。在Stash配置管理选择“从URL/链接下载”（菜单文字随版本可能不同），粘贴上面的完整地址。下载后把它命名为“Jimmy 本机配置”并明确选中它；机场链接应填写到下一步的代理集中，不能另外把机场生成的整份配置当作本项目主配置运行。
2. 在设备准备一份**本地私人覆写**，只在手机填写自己的机场URL，启用并关联这份配置。可从仓库的[占位模板](../examples/private-provider.stoverride)下载为本地文件，或使用Stash提供的本地覆写编辑入口；不要保留模板的远程更新关系。可复制的内容如下，把最后一行替换为本人订阅，其他名称不变：

```yaml
name: 本机私人订阅
proxy-providers:
  机场:
    url: https://example.invalid/REPLACE_ON_DEVICE
```

3. 暂停无关的旧覆写，检查最终合并预览：只有一个“机场”代理集、URL是本机值、18个项目组不重复。刷新“机场”，对照后台核对SS/VLESS等真实节点数，不把流量和到期提示算成节点。先在“手动节点”选一个真实节点，再把“总代理”改为“手动节点”，用“规则模式”测试普通HTTPS网站；确认能连接后，把“总代理”改为“自动节点”或所需地区池。“海外AI”默认美国，Apple/Microsoft默认DIRECT；旧UI选择可能保留，请核对。若要开屏专项，先完成下述证书设置再测试相关App。

这条公共链接负责配置，你自己的机场订阅负责节点。公共配置不会自动知道你的订阅；机场URL只需在本机填一次。不要把机场URL/token拼在公共链接后，也不要提交到GitHub或发送给维护者。格式及节点遗漏问题见[订阅兼容说明](SUBSCRIPTION.md)。

## 已有完整机场文件：合成一个本机导入文件

若私人覆写或代理集导入无法工作，可使用已经包含实际 `proxies` 的完整机场 YAML，在可信的本地电脑合成一个文件。手机用户拿到合成结果后直接导入，不需要执行下面的开发命令，也不再填写私人覆写。

```sh
python tools/build_private_config.py --input /tmp/airport.yaml --output /tmp/Jimmy-Stash-private.yaml
```

输入和输出必须放在仓库外，不使用真实订阅URL作为命令参数。工具不联网、不打印节点名/服务器/凭据，不将私人文件加入Git，输出权限为0600。它只取来源节点，保留每个节点的连接字段；常见流量/到期提示不作节点，重复名称报错，与策略组重名的节点仅加显示前缀。Reality/Vision等字段会原样保留，但不因此宣称Stash支持或已经连接成功。带链式代理依赖的来源需要另行审查，不静默删除依赖。

分流、DNS、广告规则与App专项声明继续复用当前 `config/stash.yaml`，不再另装App覆写；不继承机场旧DNS、策略组、规则、控制端口或证书。代理集引用和筛选在构建时展开为明确节点列表；“其他地区”在这个**固定快照**里是五地区之外的全部候选，名称无法识别的节点也包含在内。空地区生成仅含REJECT的select组，非空地区使用url-test且只列本地区候选和末尾REJECT；全部失效的原生行为仍待手机验收。

导入时选择这个新文件作为主配置，关闭之前为了本项目启用的覆写，保持规则模式。首次可在“手动节点”手选真实节点，再将“总代理”从REJECT改为“手动节点”进行连接诊断；日常可选择“自动节点”或有节点的地区。HTTP/MITM证书步骤与下节相同。

**这是本地节点与规则快照，不能自动更新机场节点或内嵌分流规则。** 机场变化后需取得新的完整文件，再用同一工具和当前公共源文件重新合成；App专项的主机、匹配声明变化也要重新合成；脚本改为远程URL引用，需联网加载和更新。不要将原机场的远程更新地址绑定到合成结果，否则刷新会替换回机场原分流。更新前保留旧文件和地区选择，失败时切回之前能用的配置。私人结果不上传公开仓库，也不公开托管下载。

## 已经能用的用户：现在只做这些

1. **保留原本机私人订阅覆写**，不改机场URL，不创建副本，不重装证书。
2. 如果此前另装过“广告增强”、单独淘宝/微博等广告覆写、expanded或临时诊断覆写，先停用它们。没见过或没装过这些就跳过；不要停用私人订阅覆写。
3. 在Stash配置列表找到原来的Jimmy公共配置，使用该条目的更新/重新下载功能，刷新本页开头的**同一条URL**；保持这份配置被选中。
4. 在配置文本开头确认`AD-20261020.5`，再断开并重新连接Stash。HTTP/MITM保持开启，原已完全信任的自建CA继续使用。检查“机场”仍有节点、总代理及软件地区选择仍正确。

这次更新会一起获得App专项声明、58个App精确解密主机及自检用`example.com`、11份响应脚本和1份自检脚本的URL声明，由Stash联网加载脚本。脚本URL使用`?v=AD-20261020.5`区分新版资源请求，路径不变；这不是脚本固定快照，也不能保证原生缓存永远成功更新。扩展规则集已在主配置里引用，按自身刷新间隔联网获取；若规则集下载失败，可在远程规则集页面手动刷新“基础广告”（名称保留，实际URL为`rules/vendor/ads-expanded.yaml`）。不要为它再新建expanded覆写。

开屏仍在时，在Safari打开[本机自检页](https://example.com/jimmy-stash-check)，点开始、使用相关App，再回结果页刷新即可。无需复制配置或编辑YAML；只反馈页面固定状态，详见[15分钟排查步骤](ADBLOCKING.md#自检页排查)。自检成功不能代替App命中和去广告效果验收。

**当前不需要App开关或expanded按钮。** 它们曾是旧分层安装中另行导入的覆写条目。现有专项已经整合进主配置，旧文件仅保留为维护源与安装兼容文件；停用额外同名覆写不会撤销内置动作。不要为日常使用再安装这些广告覆写。

首次使用HTTP/MITM时，才在Stash生成本机CA并安装，在iOS“设置→通用→关于本机→证书信任设置”完全信任。证书私钥只留设备。域名规则不需要解密，HTTPS重写/响应脚本需要证书；证书本身不含去广告规则。

出现正常业务异常，先把“广告拦截”切到DIRECT排查域名拦截；**这不会关闭HTTP处理**。仍异常时关闭HTTP/MITM并重连，或切回设备保存的可用配置。逐App范围、缓存和HTTP/3限制见[技术规格](AD-ARCHITECTURE.md)；多次冷启动、后台返回与正常功能仍须按[手机验收](PHONE-CHECKLIST.md)核对，不能保证全部开屏消失。

## 选地区与日常更新

“海外AI”替代原OpenAI组并默认选美国，覆盖常用海外AI服务；范围与来源见[海外AI说明](AI-COVERAGE.md)，不能穷尽所有新服务。Netflix/YouTube/Telegram和未匹配流量默认跟随总代理。各软件仍可独立选择地区池、自动节点、手动节点、总代理或具体节点。Apple/Microsoft默认DIRECT；总代理默认REJECT，首次要改成自动节点或地区。

“自动节点”平铺全部连接候选，排除常见流量/到期提示，不按国家拆分，也不按SS/VLESS协议删节点，并自动选择最低探测延迟。它与五个单地区池、“其他地区”共7池都使用原生 `url-test`，测试URL为 `https://www.gstatic.com/generate_204`，间隔1800秒。按最近成功的HTTPS探测结果选择，不是ICMP ping或下载带宽；切换阈值、缓存和时机仍待Stash实测，不保证即时最快或服务解锁。“自动节点”可能跨国家选择，五个单地区池不含其他地区或DIRECT；REJECT哨兵的空池/全失效原生行为仍需手机验证。

想手选全节点，使用保留的“手动节点”。多个软件选同一池或手动入口时，共用该入口的结果；需要固定某软件自己的具体节点，就直接在该软件组内选择。

“其他地区”按常见其他国家和地区的中文、英文、缩写、旗帜正向匹配，例如韩国、英国、德国、加拿大、澳大利亚等；它不是五个地区的严格补集，名称含糊或未收录的节点仍在“自动节点”和“手动节点”。此池现在也自动选最低探测延迟，因此可能在其中的不同国家之间切换；要求固定国家时请选择对应单地区池或手选已确认出口的节点。为了避免依赖未经核实的排除字段，本项目没有使用负向前瞻或`exclude-filter`。

**已能正常连接的用户不必重填机场URL或新建私人覆写。** 在配置列表刷新原公共主配置即可。之前“全部节点→自动节点”“OpenAI→海外AI”的更名属于历史迁移；仍使用旧组名时按[迁移记录](UPDATES.md#本次测速与海外ai调整的迁移)核对。日常更新保持现有组名，更新后仍需确认私人覆写关联和自己的地区选择。无远程更新地址的本地副本，应先在设备保留备份，再导入本页整合URL并关联原私人覆写。

以后在配置列表刷新**同一条URL**，获取公共分流、App专项声明、脚本URL和规则集引用，不重建本机私人覆写。新版首行包含#SUBSCRIBED，官方托管配置默认每12小时检查更新，可在配置设置页调整；先刷新一次原链接迁移到新版。脚本由Stash通过URL读取，并配置24小时尝试更新。新增MITM主机或handler不能仅刷新脚本替代主配置更新。扩展广告规则集与机场节点维持现有24小时自动尝试刷新间隔，主配置和资源使用不同更新入口，iOS后台不保证准点，离线缓存也不作保证。所有频率以[更新建议表](UPDATES.md)为准。刷新后检查本机覆写仍关联、机场URL仍是私人值、原组名及各软件选择仍在。界面选择和证书是否保留尚未实测；先记下选择，在设备保留私人备份，必要时重选/重新关联。

机场改了订阅URL时，仍需你在设备私人覆写中填写新地址；定期刷新只能请求当前保存的URL，不能自行发现新链接。

不要直接在会被远程刷新整份替换的公共主配置里长期保存私人URL。若当前版本无法方便使用本地私人覆写，也可先编辑下载后的主配置作为试用，但每次重新下载前都须备份并在本机重新填URL，不能承诺这种做法自动保留。

更新失败时保留当前已下载配置，不删原来能用的配置。若需要回退，使用自己本机已验收过的旧配置，或从仓库历史提交取得旧的公共配置入口，再关联原私人覆写。含真实订阅或证书的备份不上传。

## 已启动但打不开网页或出现DNS证书错误

先检查选中的是否是“Jimmy 本机配置”。本项目没有名为“Google”或“NCloud”的策略组，也未配置四个fallback DNS；如果最终配置里出现这些内容，先停用无关覆写，核对是否运行了机场生成的整份配置、旧配置，或其他本机设置覆盖了公共文件。仅凭这些名称不能确定唯一原因，应以最终合并结果为准。日志显示runtime started只证明当时有配置启动，不能反推Jimmy配置导入成功；若导入页面另有解析错误，需单独记录该错误的字段和行号。

本项目使用以下两个加密DNS地址：

```text
https://dns.alidns.com/dns-query
https://doh.pub/dns-query
```

若错误涉及 `dot.pub` 和 `NotValidForName`，表示连接时的证书名称核对未通过；它不是让你关闭证书验证的提示。本项目没有使用 `dot.pub`。同时检查Stash界面的DNS设置、已启用覆写与最终YAML，恢复以上地址，不开启 `skip-cert-verify`，也不把更换MITM证书当作DNS证书错误的修复方法。网络拦截、DNS服务端、系统时间及其他设置也可能造成TLS问题，不能把所有DNS错误都归因于主配置。

DNS设置核对后，先关闭HTTP/MITM处理，用“手动节点”手选一个真实节点测试普通HTTPS网站；不要选“剩余流量”“到期时间”等提示项。基础连接成功后，再逐步启用地区池和广告处理。仍失败时，只反馈Stash/iOS版本、选中配置名称、错误类别、问题发生在导入/启动/连接哪一步，以及是否含 `NotValidForName`；不要发送原始完整日志或含私人信息的截图。

## 验证边界

固定URL的最新发布提交、HTTP返回及内容哈希校验结果见[PROGRESS.md](../PROGRESS.md)；运行文件和来源许可分别核对，不以网页能打开代替内容校验。普通YAML/模型通过仍不等于Stash原生解析、代理连接、地区锁定、广告效果或界面选择保留已经通过。当前官方文档站受云网络策略限制，精确版本和部分原生语义待复核。手机检查见[验收清单](PHONE-CHECKLIST.md)。自动签到继续暂停。

维护者更新原配置/规则/脚本后，运行`python tools/build_subscription.py --write`重建同一入口，再执行`python tools/validate.py`。构建只改变承载方式，不另维护第二套业务逻辑。
