# 手机简明使用教程

功能范围先保持不变，自动签到继续暂停。你只需要在自己的iPhone填写机场订阅；不需要提供Cookie、手机号或账号密码。

**现在推荐一条链接导入。** 使用[订阅导入教程](SUBSCRIBE.md)中的固定URL下载完整配置，只需本机填一次私人订阅、选择地区，需要开屏专项时设置自己的证书。一体化入口已经包含原广告专项，不再逐个添加。

本地Jimmy-Stash.zip仍可按[本地包最少操作](LOCAL-IMPORT.md)使用。以下保留原分层维护教程作为备选；选择一种方式即可。一体化订阅不重复叠加core与同款广告handler。当前官方文档访问受环境网络限制，原生合并、地区池失效行为及手机效果仍待核对；配置仍是候选实现。

完整说明见[README](../README.md)。以下采用较少步骤的方式：把订阅地址写入设备端的本地主配置，公共内容通过覆写更新。不要再同时维护另一份不同地址的私人覆写。

## 1. 保留原来能用的配置

如果Stash已有能用的配置，先保留它，另建本项目配置。个人备份只保存在自己的设备或私人存储。首次设置完成前，不删除原配置。

## 2. 导入本地主配置并填订阅

公共文件发布后，在iPhone Safari打开：

```text
https://raw.githubusercontent.com/Panzm6111/Jimmy-s-Stash-rules/main/config/main.yaml
```

下载到“文件”App，再通过共享菜单中的Stash或Stash本地文件导入入口导入，命名为“Jimmy 本机主配置”。菜单名称可能随版本变化。

在Stash的这份**本地配置**编辑入口中，找到唯一一处：

```text
https://example.invalid/REPLACE_ON_DEVICE
```

将它完整替换为你的机场订阅链接，其他内容保持不动。保存后只留在设备，不在GitHub网页填写、不发给维护者。

机场后台有“Stash”格式就优先选它。没有时先看[订阅兼容教程](SUBSCRIPTION.md)，不要把订阅发给第三方转换站。导入成功不代表SS、VLESS节点全都保留或可连接。

## 3. 添加公共分流覆写

在Stash的覆写管理中添加远程覆写，地址为：

```text
https://raw.githubusercontent.com/Panzm6111/Jimmy-s-Stash-rules/main/config/core.stoverride
```

启用它，并应用到“Jimmy 本机主配置”。查看最终配置/合并预览，确认有一个“机场”代理集、16个本项目策略组，机场URL仍是本机填写的值。不要分享带订阅地址的预览。

如果Stash报错、缺组或合并顺序不符，保持原配置使用，按[反馈方法](PHONE-CHECKLIST.md)只提供错误类别与版本信息。离线检查不能替代Stash自身接受配置。

## 4. 更新机场、选择地区并连接

1. 在代理集页面刷新“机场”，对照机场后台核对节点数量，尤其是SS和VLESS。
2. 在策略组页面，把“总代理”从初始 `REJECT` 改为你想用的地区池：美国、日本、香港、新加坡或台湾。地区中必须有可用节点。
3. OpenAI、Netflix、YouTube、Telegram默认跟随“总代理”。想单独选地区，就进入该软件组改选地区池；各软件可以不同。
4. 想固定具体节点，直接在该软件组选择一个节点。“手动节点”组是共享入口，多个软件选它时会共用该手动选择。
5. Apple、Microsoft先保持默认直连。“广告拦截”保持 `REJECT`。
6. 选择Stash的“规则”模式，再连接并按系统提示允许VPN。先检查一个国内服务和一个所需海外服务，再逐项做[手机验收](PHONE-CHECKLIST.md)。

示例：“总代理=日本，OpenAI=美国，Netflix=香港”。这只是操作示例，不是项目替你预设地区。延迟变绿不代表服务解锁；空池/全部失效的原生行为尚未实测，不宣称已保证严格地区出口。

## 5. 添加去广告模块

主配置加公共分流后，基础广告域名规则已参与工作，不需要证书。

需要更多域名拦截时，另加可选“扩展广告”覆写：

```text
https://raw.githubusercontent.com/Panzm6111/Jimmy-s-Stash-rules/main/modules/ads/expanded.stoverride
```

针对某款App，从[广告模块目录](AD-MODULES.md)复制该行的“远程覆写地址”，在Stash覆写管理中添加、关联主配置并启用。淘宝、小红书、微博、京东、拼多多等各有独立开关。**先加一款、验收一款，再加下一款。**

目录标“无需MITM”的模块可以先用；云闪付、京东金融、铁路12306等只处理指定广告域名。扩展包可能已包含相同域名，目录列明重叠，不必为同一作用重复添加。

目录标“需MITM”的模块，才需要下面的证书步骤。

## 6. 为需要的专项设置证书

MITM让Stash能够读取列出的HTTPS主机内容；虽然处理只匹配广告路径，解密范围仍是整个指定主机。接受这一范围后再启用对应模块。

1. 在Stash的HTTP/MITM或证书设置中，**在自己的设备生成**CA证书。
2. 按Stash提示安装描述文件；系统可能要求到“设置→通用→VPN与设备管理”完成安装。
3. 到“设置→通用→关于本机→证书信任设置”，完全信任自己刚生成的Stash证书，再回Stash启用HTTP/MITM。具体入口依当前版本官方说明核对。
4. 只使用模块声明的精确域名，不额外添加全域名、银行或支付主域，不关闭TLS证书校验。
5. 退出目标App再打开，检查广告及正常登录、消息、播放、查物流/定位和普通领券。不要为验收实际下单或消费。

证书私钥只留在设备。脚本不清除App已有广告缓存；广告仍在、出现等待/空白或证书报错时，先关闭该模块，不能据此认为需要扩大解密范围。微信公众号模块仅处理文章广告，不含朋友圈或视频号。

## 7. 日常使用、更新与恢复

日常保持“连接＋规则模式”：国内和局域网按规则直连，海外服务按软件策略组处理。关闭Stash会停止本项目的分流及去广告。没有自动签到任务。

更新时先记下各软件选的地区，在覆写管理里刷新**原来的公共分流/广告条目**并重新应用；按需刷新规则集、脚本和机场。不要每次重新导入主配置，也不要删掉本机订阅。各类资源的更新机制不同，不能保证覆写本身自动更新；详细边界见[更新教程](UPDATES.md)。更新后核对私人URL和地区选择，丢失的选择按自己的记录重选。

| 遇到的问题 | 最少恢复步骤 |
|---|---|
| 登录、支付、消息、视频或券异常 | 先将“广告拦截”改为 `DIRECT`；仍异常就关闭相关广告覆写并重建连接 |
| 只想停止某款专项 | 在覆写管理关闭该款；`DIRECT`只放行域名规则，不停止HTTP重写/脚本 |
| 专项关闭后同一广告域名仍被拦 | 检查扩展包是否包含它；必要时关闭扩展包或加本机精确白名单 |
| 全部断网、配置报错或地区池异常 | 切回保留的原配置；必要时停止Stash。只反馈版本、模块名和错误类别，不发订阅/请求头/响应体 |
| 更新后出问题 | 切回在本机保存的上一套已验收公共配置及配套资源，保留私人订阅；只回退core不能保证规则/JS也一起回退 |

已有可工作配置可以先保留。公共链接的实际下载校验看PROGRESS，首次导入仍需完成Stash原生与手机验收。
